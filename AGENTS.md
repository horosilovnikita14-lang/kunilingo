# Обязательные правила разработки KuniLingo

Перед изменениями интерфейса прочитать [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) и соблюдать его во всех вкладках. Внешний вид комнаты, постановка сцены, шрифты, цвета, сетка и анимации согласованы с пользователем; сохранять их при доработке содержания и функций.

- Общие элементы оформлять через `app/study-system86.css`, поведение раскрытия и выбора — через `app/study-controls86.js`.
- Не заводить отдельные шрифты, цвета интерфейса, тайминги, стрелки и системные видимые select/checkbox для очередной вкладки. Палитра свободного карандаша относится к рисункам пользователя, а не к новой палитре интерфейса.
- Левое и правое стекло должны использовать одни `--study-glass-*` переменные.
- Постоянные заголовки зелёные; активный выбор и основные действия медные.
- Не скрывать раскрывающийся контент до завершения обратной анимации. Сохранять клавиатуру, фокус, reduced motion, прокрутку, черновики, пометки и пользовательский прогресс.
- Справочную теорию хранить по категориям. В Практике автоматически показывать только материалы категорий конкретной карточки; номер ЕГЭ не означает показ всей теории номера или соседних тем. Полные учебные справочники Пути сохраняются отдельно.
- Использовать существующие коды ФИПИ и тематические метки как основу. План массовой автоматизации описан в [docs/automatic-topics.md](docs/automatic-topics.md); смысловой классификатор ещё не подключён. Не выдавать план за готовую функцию.
- Привязки хостинга и данные доступа не являются исходниками. Публикация сайта не следует из локальной правки или сохранения кода в GitHub.
- Действующие запросы пользователя имеют приоритет. Этот файл не вводит дополнительных согласований и не разрешает публикацию.

Команды установки, сборки и самодостаточных тестов: [README.md](README.md). После изменений выполнять относящиеся к ним проверки. Для визуальных изменений автоматические тесты дополнять просмотром текущего интерфейса, когда он доступен; ограничения проверки сообщать честно.
